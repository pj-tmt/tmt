不論在指令列、Squad board 或這個網站，tmt 都使用同一套樣式。這頁是三者共用的準則。所有值都來自同一個檔案 [`design/tokens/tokens.json`](https://github.com/pj-tmt/tmt/blob/main/design/tokens/tokens.json)；網站的樣式表與本頁的每個表格都直接讀取它，不用手動複製。

<Mdx.h3 id="principles">原則</Mdx.h3>

- **顏色有意義。** 畫面大部分保持中性。只有需要你處理、正在工作或卡住的項目會突出顯示。
- **不只靠顏色。** 每個狀態也會用標記或文字顯示，例如 `◆2` 或 `blocked`，讓 `NO_COLOR`、pipe、螢幕閱讀器或色盲使用者都能辨識。
- **色調由你的終端機決定。** 指令列的 token 對應終端機的 16 色之一，所以會沿用使用者的主題。網站與全螢幕 board 的 truecolor 主題則使用下面列出的確切值。
- **同一套用詞。** 每個 token 在所有地方都有同一個意思：`waiting` 永遠表示需要你處理的事，不論是在 board 的頁籤、`tmt ls` 的一列，或網站上的徽章。

CLI 自己的 token 名稱（`accent`、`ok`、`warn`、`error`、`dim`，以及 driver 的顏色）都會對應到這些值：`ok` 是 `working`、`warn` 是 `waiting`、`error` 是 `blocked`，Claude 與 Codex driver 的顏色則是 `review` 與 `link`，如 [design/cli-style.md](https://github.com/pj-tmt/tmt/blob/main/design/cli-style.md) 所列。終端機主題從同一個檔案讀取數值；兩者不一致時，測試就會失敗。
