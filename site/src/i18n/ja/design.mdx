コマンドライン、Squad の board、このサイトのどこでも、tmt は同じ製品として見えるようにします。このページは共通の指針です。値は1つのファイル、[`design/tokens/tokens.json`](https://github.com/pj-tmt/tmt/blob/main/design/tokens/tokens.json) にあります。サイトのスタイルシートとこのページのすべての表がそこから読み取るので、手作業でコピーした値はありません。

<Mdx.h3 id="principles">基本方針</Mdx.h3>

- **色に意味を持たせます。** 画面の大部分は落ち着いた色にし、ユーザーの対応が必要なもの、作業中のもの、行き詰まったものだけを目立たせます。
- **色だけに頼りません。** 状態は `◆2` や `blocked` のように記号や言葉でも表します。`NO_COLOR`、パイプ、スクリーンリーダー、色の見え方の違いがあっても伝わります。
- **端末の色合いは端末に任せます。** コマンドラインの token は端末の16色のいずれかを指定し、ユーザーのテーマを尊重します。サイトと全画面 board の truecolor テーマは、下記の値をそのまま使います。
- **意味を統一します。** token はどこでも同じ意味を持ちます。`waiting` は board のタブでも、`tmt ls` の行でも、このサイトのバッジでも、ユーザーの対応が必要なものを示します。

コマンドライン独自の token 名（`accent`、`ok`、`warn`、`error`、`dim`、driver の色）も、これらの色のいずれかで表示します。`ok` は `working`、`warn` は `waiting`、`error` は `blocked`、Claude と Codex の driver 色はそれぞれ `review` と `link` です。[design/cli-style.md](https://github.com/pj-tmt/tmt/blob/main/design/cli-style.md) に一覧があります。端末のテーマも同じファイルから値を読み、両者が異なればテストが失敗します。
