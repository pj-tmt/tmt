tmt looks like one product wherever you meet it: the command line, the Squad board and this site. This page is the guideline they share. The values come from one file, [`design/tokens/tokens.json`](https://github.com/pj-tmt/tmt/blob/main/design/tokens/tokens.json); the site's stylesheet and every table on this page read it, so nothing here is copied by hand.

### Interactive design guidebook (MDX)

The [browser interface guide](https://github.com/pj-tmt/tmt/blob/main/design/gui-style.md) owns the header, cards, controls, overlays, focus and recovery wording. The [CLI guide](https://github.com/pj-tmt/tmt/blob/main/design/cli-style.md) owns terminal output. Start here to see the rules in use, then follow those guides for the full contracts.

### Principles

- **Color carries meaning.** Most of a screen stays neutral. Only what needs you, what's working and what's stuck stands out.
- **Never color alone.** Every state also shows as a mark or a word, such as `◆2` or `blocked`, so it survives `NO_COLOR`, a pipe, a screen reader or color blindness.
- **Your terminal decides the shade.** On the command line a token names one of the terminal's 16 colors, so the user's theme wins. The site and the full-screen board's truecolor themes use the exact values below.
- **One vocabulary.** A token means the same thing everywhere: `waiting` is always something that needs you, whether it's a tab on the board, a row in `tmt ls` or a badge on this site.

The command line's own token names (`accent`, `ok`, `warn`, `error`, `dim`, and the driver colors) each show as one of these: `ok` is `working`, `warn` is `waiting`, `error` is `blocked`, and the Claude and Codex driver colors are `review` and `link`, as [design/cli-style.md](https://github.com/pj-tmt/tmt/blob/main/design/cli-style.md) lists. The terminal's themes read their values from the same file, and a test fails if the two ever differ.
