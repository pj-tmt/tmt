### Connect it

<Cmd>{`
$ tmt setup codex           # shows the exact config change, then asks
$ tmt run builder codex     # start Codex as "builder"
$ tmt resume builder        # reopen builder's own thread
`}</Cmd>

Setup adds Codex's lifecycle hooks for tmt. Codex asks you to trust new hooks the first time; that's expected. `tmt setup codex --remove` takes them out again.

### Message delivery

`tmt run <name> codex` and `tmt resume <name>` use Codex's native message channel by default on Codex versions tmt has tested. `talk` queues input through a private app-server without pasting into the pane or interrupting your typing. Each channel session has one extra owned app-server process and a supervisor; tmt cleans them up when its foreground exits, including Ctrl-C.

The [run and resume options](/working#tmt-run) let you choose plain paste delivery or require a channel.

<Cmd>{`
$ tmt run --no-channel builder codex  # plain paste delivery
$ tmt resume --channel builder       # require the channel for this exact thread
`}</Cmd>

If tmt has not tested your Codex version or cannot set up the channel safely before startup, the default launches the original plain command and prints one line: `warning: tmt: builder uses paste delivery: <reason>`. If the pane may already be attached to a channel, tmt refuses to fall back to paste. Once enrolled, a channel that is not ready or cannot deliver stays an error; tmt never pastes into that pane instead.

Codex may ask you to trust the launch folder. Answer that prompt yourself in its TUI. tmt never answers it or changes trust settings, and input already accepted into the queue may wait until you complete attachment. Running plain `codex` is unchanged; tmt changes no global Codex configuration, authentication or hooks for channel enrollment.

### Codex's sandbox

In Codex's workspace-write sandbox, Codex can't write tmt's data directory by default. tmt reports this plainly as `STORAGE_NOT_WRITABLE` with the directory's path, not as a crash. Either allow that directory, for example by adding it to Codex's `writable_roots`, or let Codex run the command with its own escalation. tmt never changes Codex's sandbox settings, and an agent shouldn't change that setting without your OK.

### Usage counters

`tmt setup codex --usage` adds a turn-end hook that records Codex's context size and the tokens its completed requests used; [Usage counters](/drivers#usage-counters) lists the fields. Codex states its context window, so `windowTokens` is filled in. Codex's counters follow the provider's own running totals: the first reading is the starting point, and later turns add to it.
