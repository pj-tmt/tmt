### Delivery you can trust

Before typing into a pane, tmt checks that the pane still belongs to the name you addressed, on the same tmux server. If sending may have partly happened (for example, the text was pasted but Enter wasn't confirmed), tmt reports it as **uncertain** and never sends again on its own. Look with `tmt check <name>` first, then decide.

### The pane badge

Each named pane shows a small label in its border. It is on by default:

<BadgeBorders />

<Cmd>{`$ tmt config set ui.paneBadge off --global   # turn it off`}</Cmd>

tmt shows the label on the bound pane only: it sets that pane's own `pane-border-format` to your current format with the badge in front, and never touches your global, session or window options or your `~/.tmux.conf`. `tmt unbind` or turning the badge off removes what tmt added. A pane format you set yourself is left alone, and if your format already places the badge, tmt adds nothing. If pane borders are hidden in that window, tmt prints the command that shows them instead of changing it. To place the badge yourself, add this fragment to your `pane-border-format`:

<Code>{`#{?@tmt.badge, [#{@tmt.badge}],}`}</Code>

The dot shows the recorded session state, not whether the agent is busy.

### When tmux says no

Some agent sandboxes block access to the tmux socket. tmt then says so: it can't access the socket, a sandbox may be blocking it, and no input reached any pane. It doesn't report the pane as missing. The fix is on the agent's side: rerun the same command with the agent's own escalation, or allow the socket.
