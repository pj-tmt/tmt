An extension is any executable named `tmt-<name>` on your PATH. There's no manifest, registry or install step: put the file on PATH and `tmt <name>` runs it. Ops is built exactly this way, with no extra access.

### 1. Name it

The name uses lowercase letters, digits and hyphens (`[a-z0-9][a-z0-9-]*`). Built-in commands and their aliases always win, so pick a name tmt doesn't already use. `tmt help` lists the extensions it found and flags any that a built-in shadows.

<Cmd>{`
$ install -m 755 tmt-hello ~/.local/bin/
$ tmt hello --loud        # runs: tmt-hello --loud
$ tmt help hello          # runs: tmt-hello --help
`}</Cmd>

### 2. What your program receives

<Terms>
  <dt>arguments</dt>
  <dd>
    Everything after the name, passed through verbatim. tmt doesn't parse your options. tmt's own
    options can't come before your name.
  </dd>
  <dt>terminal</dt>
  <dd>
    tmt replaces itself with your program, so you get its stdin, stdout, stderr, TTY and signals
    directly. Your exit code becomes tmt's exit code.
  </dd>
  <dt>TMT_EXECUTABLE</dt>
  <dd>
    The absolute path of the tmt that launched you. Always call back through it instead of whatever{" "}
    <code>tmt</code> is on PATH, so you talk to the same install and data.
  </dd>
</Terms>

### 3. Tab completion (optional)

If you want completion, handle one extra call. tmt runs `tmt-<name> __complete -- <words>`, where the words are everything after your name, including the one being typed. Print one literal candidate per line. You get one second and 64 KiB. Empty output, an error or a timeout falls back to ordinary file completion, and candidates are never evaluated by the shell.

### 4. Talk to tmt

Never open tmt's database yourself. Use the same doors as any other program:

- **Ordinary commands with `--json`** for anything a person would also run: `whoami`, `identity show`, `list`, `room show`, `x`, `reply`, `result`.
- **`tmt api`** for machine-shaped work: one versioned JSON request on stdin, one JSON answer on stdout. The full contract is in [contracts/extension-api.md](https://github.com/pj-tmt/tmt/blob/main/contracts/extension-api.md).

<Cmd>{`
$ printf '%s' '{"version":1,"operation":"capabilities","input":{}}' | "$TMT_EXECUTABLE" api
{"version":1,"supported":{"min":1,"max":1},"operations":["capabilities","storage.root",
 "changes.cursor","requests.list","requests.show","dispatch.show","dispatch.create", ...],...}
`}</Cmd>

| Operation            | Use it to                                                                                                                                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| storage.root         | Find tmt's data directory. Keep your own files under `<dataRoot>/<your-name>/`, and never open tmt's database or settings.                                                                                    |
| requests.list / show | Page through request history for an agent or room, or with `"view":"results"` the newest finished replies to one agent's requests, and read one request with its reply. Reading never marks anything as read. |
| dispatch.create      | Send work to one or more agents. You choose an `operationId` first; sending the same one again returns the original receipt and never sends twice.                                                            |
| dispatch.show        | Recover the receipt for an `operationId` after a crash or timeout.                                                                                                                                            |
| rooms.write          | Create or change a room, using its current revision so concurrent edits don't overwrite each other.                                                                                                           |
| notes.read           | Read a saved agent's notes by its ID.                                                                                                                                                                         |

These are the main ones; `capabilities` lists every operation the installed tmt supports.

<Aside title="Writes name who's writing.">
  Writes (<code>dispatch.create</code>, <code>rooms.write</code> and <code>rooms.retire</code>) name
  one originator: an <code>identity</code>, or <code>"originator":"anonymous"</code> to store no
  writer, exactly like the CLI without <code>--identity</code>. Naming both or neither is refused.
  This is a local interface for the same user, not a security boundary: it records who acted and
  grants nothing extra.
</Aside>

### A complete example

<Code>{`
#!/bin/sh
# tmt-hello: say hello as the agent in this pane.
set -e
if [ "$1" = "__complete" ]; then printf '%s\\n' --loud; exit 0; fi
if [ "$1" = "--help" ]; then echo "usage: tmt hello [--loud]"; exit 0; fi
me=$("$TMT_EXECUTABLE" whoami --json) # fails clearly outside a named pane
greeting="hello from $(printf '%s' "$me" | sed -n 's/.*"name":"\\([^"]*\\)".*/\\1/p')"
[ "$1" = "--loud" ] && greeting=$(printf '%s' "$greeting" | tr a-z A-Z)
echo "$greeting"
`}</Code>

### 5. React to changes (optional)

An extension on PATH runs only when someone invokes it. To react when identities and rooms change, it needs the user's explicit consent:

<Cmd>{`
$ tmt extension hooks enable hello    # trust tmt-hello on PATH
$ tmt extension hooks ls
$ tmt extension hooks disable hello
`}</Cmd>

Enabling requires an executable the user owns, with neither the file nor its directory writable by anyone else, and records exactly that file; after an upgrade or any change, the user enables it again. After a command has committed, tmt runs `tmt-<name> __tmt-hooks 1 observe` with the events (an identity or a room created, renamed or retired) as JSON on stdin. Hooks receive only IDs and states, never names or messages, and can't block or change a command. Treat an event as a nudge to look again: events can be dropped or repeated.

An extension with hooks enabled can also add one informational line, at most 240 characters, to `tmt whoami --context`, to the context an agent receives when a session starts and, once `tmt setup` has installed the prompt hook, to the context of each prompt. tmt names the extension and labels the line `(informational)`, so never phrase it as an instruction. The event and field contract is in [contracts/extension-api.md](https://github.com/pj-tmt/tmt/blob/main/contracts/extension-api.md).
